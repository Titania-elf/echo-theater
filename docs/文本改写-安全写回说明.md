# 文本改写与前端兼容

改写和删除现在使用原文位置补丁，保留消息中的正文标签、状态数据、HTML、脚本、样式及代码区域。只有原文和当前显示都能可靠定位的正文才会自动写回。

例如：

```html
<正文>他很愤怒。</正文>
<状态栏>信任：尚未恢复</状态栏>
```

只修改正文后：

```html
<正文>他攥紧了拳头。</正文>
<状态栏>信任：尚未恢复</状态栏>
```

建议在改写设置的“提取白名单”里填写实际正文标签，例如 `正文` 或 `content, dialogue, narration`。支持中文标签；配置的标签未出现时会停止提取，不再回退到整条消息。

当前版本支持能够对应到酒馆消息中静态文本的正文，包括一些通过显示正则包裹的正文。写回只修改已有文本节点，不重渲染消息、不重载聊天，也不发送可能让第三方插件重建前端的通用消息编辑事件。故事记忆通过专用通知更新。

以下情况会保留在 Diff 或删除结果中，标为“仅预览”，并说明原因：

- 正文只显示在 iframe、Vue/React 等动态组件内，或当前楼层尚未挂载。
- 一个改写单元跨越原文标签，或涉及暂不支持的 Markdown 格式。
- 独立显示缓存与原文不同，或多个相同段落无法唯一定位。
- 请求期间切换聊天、切换 swipe、修改原文，或酒馆仍在生成。
- 改写结果引入 HTML、Markdown 标记或新的换行结构。

一批结果可以部分写回；未应用的条目不会偷偷存入原文，也不会等待重载后生效。状态栏会显示实际写回与仅预览的数量。

保存后会回读楼层确认结果。无法确认时撤回仍属于本次操作的改动，并尝试保存恢复后的原文；不会覆盖期间产生的新编辑。请留意界面的保存状态。

“选句改写”使用浏览器文本高亮，不再向正文插入包装标签。楼层旁会提供句子列表，因此不支持文本高亮的浏览器仍可选句。改写前端组件内部的正文需要后续为对应组件增加专用适配。
