# 故事记忆（第一版）

入口：发送键旁的工具箱菜单 → **故事记忆**；也可从回声小剧场主界面「更多」进入，并固定到标题栏。

打开角色聊天后，开启 **后台自动整理**。开关按聊天保存；开启后会检查已有历史，也会在正常角色回复结束后继续检查。无需逐次确认。暂停自动整理后，已有记忆继续注入。

## 自动整理流程

1. 保留最近至少16楼，并把保留窗口向前延伸至完整对话的用户楼。
2. 较早的可读正文达到约6000 token，或32楼时，读取一段完整对话。单次正文读取上限约12000 token。
3. 模型返回本段摘要、全程历史脉络、截至整理范围的剧情状态，以及本次新增或变化的人物关系和伏笔条目。
4. 完整JSON、必需字段和条目的原文摘录通过校验后，先保存记忆。回读提交标识确认落盘，再隐藏对应正文并保存隐藏标记。
5. 后台追赶已有历史时逐段处理；正常聊天无需等待模型总结。正在构造回复时，新的总结先等待；已开始的保存会在构造提示词前完成。

「立即整理」可以跳过触发量，整理最近保留窗口之前的正文。它也保留最近对话。

总结不会读取原先由用户或其他插件隐藏的正文。超大的单组对话会保留原文并提示调整读取上限，不截断后推进覆盖范围。模型请求失败、结构不完整、原文依据不符或保存失败时，正文保留；自动重试间隔为1、2、4分钟，之后最多5分钟。

## 界面

- **当前剧情**：顶部是整理进度与四项统计（整理段数 / 人物关系 / 未解决伏笔 / 待确认建议），统计块可点击跳转；历史脉络以时间轴呈现，剧情状态以「此刻」卡呈现。最新进展继续由最近正文提供。可人工编辑。
- **人物关系**：关系图 + 卡片。关系标题拆成双方头像与箭头，一眼看出方向；支持搜索、筛选、锁定/待确认标记；待确认建议置顶显示「现在 → 建议」，来源楼层可直接点开原文。
- **伏笔与约定**：关系图 + 卡片；按「未解决」「有进展」「已解决」分组，支持状态筛选与搜索，已解决默认折叠。未被新正文提及的事项保留；明确解决后归档。
- **整理记录**：每段的覆盖范围、摘要、原文和撤销入口。分段摘要编辑修改归档记录；当前注入内容可在「当前剧情」编辑。
- **注入预览**：查看独立提示词中的记忆，以及预计token、预算遗漏和超出目标预算的情况。
- **运行设置**：点击窗口顶部栏的齿轮，打开独立的运行设置窗口。可选整理时用哪个API方案（或跟随工具箱当前方案；用哪个模型由方案决定，不再单独指定）；设置最近多少楼不整理、正文攒到多少才开始整理、一次读多少、一次最多写回多少token（模型回复上限）、记忆注入占多少预算、每次直接注入最近几段摘要、最近分段占多少预算、每次召回几段旧事、召回占多少预算、插在对话的哪个位置。token 类数值不再写死上限，可按所用模型自由填写；设置在各聊天间共用。

条目可手动新增、编辑及锁定。人工编辑过的条目会保留原文；自动整理提出的新内容作为建议展示。可以采用或忽略建议。来源与变化记录能查看原文摘录、覆盖范围和历史版本。

## 注入与预算

记忆以独立键 `TITANIA_STORY_MEMORY` 持续注入酒馆原生提示词，不创建聊天楼层。默认使用system角色、聊天内深度4；深度可调整。分段完整摘要保存在聊天中，日常注入历史脉络、剧情状态、当前关系和未解决事项。

默认目标预算约2400 token。历史脉络、剧情状态和锁定的有效条目完整保留，其余条目按最近更新优先加入。预算未容纳的条目仍保存在界面中；预览明确列出遗漏。必需内容超过目标时会显示超预算，可精简或提高预算。这里的token统计是估算。

伏笔记忆是历史背景，不是下一轮任务清单。默认提示词要求模型区分角色知情与读者知情，不根据时间推断伏笔已解决，也不集中兑现伏笔。

## 最近分段直注

每段正文整理后会留下一份 `summary`，这份摘要只压缩过一次，之后不会再被后续整理改写。注入时会直接带上最近几段的原始摘要（默认 2 段），排在历史脉络之前；提示词明确要求两者不一致时以最近分段为准。

- **独立预算**：「最近分段摘要最多占多少 token」默认 1000，不挤占历史脉络和旧事召回。
- **优先最近**：预算不足时从最新一段往回挑，放不下的整段略过，不会截断句子；预览会列出未容纳的段落。
- **不重复召回**：已经由最近分段直接注入的段落，不会再被旧事召回注入一次。
- **可关闭**：把「每次直接注入最近几段摘要」或它的预算设为 0 即可。

## 旧事召回（不需要 embedding）

整理会把较早正文压成摘要，压得越多细节越容易走失。启用召回后，插件在每次构造提示词前，用最近 4 条可见正文作为查询，在已整理段落的摘要和条目原文摘句里做本地 BM25 匹配（中文按字二元组切词），把最相关的旧段落重新注入。

- **完全在本地运行**：不调用 embedding、不装任何库、不向外部发送请求。索引只在内存中按聊天与记忆版本重建，不写入聊天存档或扩展存储，手机上无需任何安装步骤。
- **独立预算**：召回内容受「召回内容最多占多少 token」限制，不挤占历史脉络、关系与伏笔的预算；放不下的整段略过，并在「注入预览」里列出。
- **可关闭**：默认每次最多召回 4 段。把「每次最多召回几段旧事」或「召回内容最多占多少 token」设为 0 即可关闭。
- **按关键词相关，不是必然相关**：召回依据是最近对话里的名字与用词，模型仍应按最近正文判断是否采用。注入预览会列出本轮召回了哪些段落。
- **细节锚点**：整理时逐字校验过的原文摘句会挂回对应段落一起检索；召回时摘要里没有的原句会作为「原文摘句」一并注入，作为不易被改写的事实锚点。

## 修改、分支与撤销

记忆和来源标记随酒馆聊天保存。不同聊天独立；酒馆创建分支时复制记忆，加载后按实际保留正文校验，保留分叉点之前的有效分段，撤回越过分叉点的分段及其依赖信息。

修改、删除或切换已整理楼层的回复版本时，从首个失效分段起撤回摘要、恢复本功能隐藏的正文，然后自动重新整理。

「撤销最近整理」或「撤销全部整理」会恢复对应正文并暂停后台自动整理，避免立即重新隐藏。原先由用户或其他插件隐藏的楼层保持原状。不依赖被撤回正文的手工条目保留。

## 验证

运行 `npm run test:memory` 验证切分、严格校验、增量条目、预算、最近分段直注、中文切词与 BM25 召回、保存失败、继续聊天、切换聊天、旧楼修改、分支、恢复和界面操作。运行 `npm test` 检查现有功能回归，`npm run build` 更新实际加载的 `index.js`。

第一版未加入向量检索；长聊天通过连续历史脉络及独立关系、伏笔条目维持记忆。自动摘要的准确性仍取决于所选模型，可以在界面修正和锁定。
