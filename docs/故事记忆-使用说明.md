# 故事记忆（第一版）

入口：发送键旁的工具箱菜单 → **故事记忆**；也可从回声小剧场主界面「更多」进入，并固定到标题栏。

打开角色聊天后，开启 **后台自动整理**。开关按聊天保存；开启后会检查已有历史，也会在正常角色回复结束后继续检查。无需逐次确认。暂停自动整理后，已有记忆继续注入。

## 自动整理流程

1. 保留最近至少16楼，并把保留窗口向前延伸至完整对话的用户楼。
2. 较早的可读正文达到约6000 token，或32楼时，读取一段完整对话。单次正文读取上限约12000 token。
3. 模型返回本段摘要、全程历史脉络、截至整理范围的剧情状态，以及本次新增或变化的人物关系和伏笔条目。
4. 完整JSON、必需字段和条目的原文摘录通过校验后，先保存记忆。回读提交标识确认落盘，再隐藏对应正文并保存隐藏标记。
5. 后台追赶已有历史时逐段处理；正常聊天无需等待模型总结。正在构造回复时，新的总结先等待；已开始的保存会在构造提示词前完成。

「立即整理」可以跳过触发量，整理最近保留窗口之前的正文。它也保留最近对话。

总结不会读取原先由用户或其他插件隐藏的正文。超大的单组对话会保留原文并提示调整读取上限，不截断后推进覆盖范围。模型请求失败、结构不完整、原文依据不符或保存失败时，正文保留；自动重试间隔为1、2、4分钟，之后最多5分钟。

## 界面

- **当前剧情**：连续历史脉络、截至已整理范围的剧情状态。最新进展继续由最近正文提供。可人工编辑。
- **人物关系**：独立条目记录方向、态度、变化原因、矛盾与知情边界。
- **伏笔与约定**：独立记录悬念、承诺和未完成目标，状态为「未解决」「有进展」「已解决」。未被新正文提及的事项保留；明确解决后归档。
- **整理记录**：每段的覆盖范围、摘要、原文和撤销入口。分段摘要编辑修改归档记录；当前注入内容可在「当前剧情」编辑。
- **注入预览**：查看独立提示词中的记忆，以及预计token、预算遗漏和超出目标预算的情况。
- **运行设置**：选择工具箱已有API方案或跟随当前方案，可单独覆盖总结模型；修改读取、触发、保留、注入预算和深度参数。设置在各聊天间共用。

条目可手动新增、编辑及锁定。人工编辑过的条目会保留原文；自动整理提出的新内容作为建议展示。可以采用或忽略建议。来源与变化记录能查看原文摘录、覆盖范围和历史版本。

## 注入与预算

记忆以独立键 `TITANIA_STORY_MEMORY` 持续注入酒馆原生提示词，不创建聊天楼层。默认使用system角色、聊天内深度4；深度可调整。分段完整摘要保存在聊天中，日常注入历史脉络、剧情状态、当前关系和未解决事项。

默认目标预算约2400 token。历史脉络、剧情状态和锁定的有效条目完整保留，其余条目按最近更新优先加入。预算未容纳的条目仍保存在界面中；预览明确列出遗漏。必需内容超过目标时会显示超预算，可精简或提高预算。这里的token统计是估算。

伏笔记忆是历史背景，不是下一轮任务清单。默认提示词要求模型区分角色知情与读者知情，不根据时间推断伏笔已解决，也不集中兑现伏笔。

## 修改、分支与撤销

记忆和来源标记随酒馆聊天保存。不同聊天独立；酒馆创建分支时复制记忆，加载后按实际保留正文校验，保留分叉点之前的有效分段，撤回越过分叉点的分段及其依赖信息。

修改、删除或切换已整理楼层的回复版本时，从首个失效分段起撤回摘要、恢复本功能隐藏的正文，然后自动重新整理。

「撤销最近整理」或「撤销全部整理」会恢复对应正文并暂停后台自动整理，避免立即重新隐藏。原先由用户或其他插件隐藏的楼层保持原状。不依赖被撤回正文的手工条目保留。

## 验证

运行 `npm run test:memory` 验证切分、严格校验、增量条目、预算、保存失败、继续聊天、切换聊天、旧楼修改、分支、恢复和界面操作。运行 `npm test` 检查现有功能回归，`npm run build` 更新实际加载的 `index.js`。

第一版未加入向量检索；长聊天通过连续历史脉络及独立关系、伏笔条目维持记忆。自动摘要的准确性仍取决于所选模型，可以在界面修正和锁定。
