# 小剧场场景配图

## 使用入口

- 新版主界面：正文右侧图片图标。
- 经典主界面：内容工具中的「场景配图」。
- 收藏阅读页：顶栏图片图标。分组收藏可在面板中选择具体一轮。

默认使用当前一轮的完整正文。可以在「正文与人物资料」中调整本次素材、补充人物外观；这些信息只用于配图，不修改剧场正文或酒馆角色卡。

## 流程与分工

配图分两步，由两个不同的执行者完成：

1. **分析画面**（本插件的 API 方案）：通读正文，选出一个适合画成单幅插图的瞬间，产出中文画面描述、原文摘录与英文生图提示词。送进模型的消息由**选景预设**决定，见下一节。
2. **生成图片**（Cosmos Vision）：把小剧场给出的提示词交给 Cosmos，由它按自己的配置出图。

点击「分析画面」后预览中文画面描述和原文摘录（摘录由模型从正文里逐字复制，对不上就丢掉那一行——画面本身照常留用），展开后可以编辑全局正负提示词、人物提示词与位置。点击「换个画面」重新运行选景（会把此前选过的画面作为排除参考）；再次点击「生成图片」沿用当前提示词，重新请求图片。

**提示词只写「画面里有什么」。** 质量词、画师串、UC 词、画风预设、LoRA 触发词与画幅采样器一律由 Cosmos Vision 追加，小剧场不写也不该写——重复填写会导致叠加。因此面板里显示的提示词**不等于**最终发给后端的内容。

**画面张数与来源不可控。** 由 Cosmos 自己的设置决定：出图张数按它的 `imageCount`，图源与模型按它的当前配置。小剧场无法指定，也不会替你切换。

接口未安装、就绪状态变化或旧版接口时，面板显示具体状态（区分「未安装」「旧版接口」「已连接」），也可以点击「重新检测」。已保存图片的浏览、采用、下载和导出不依赖 Cosmos 在线。

## 人物外观档案

选景时只有一份「人物资料」可用，默认空着。角色换个场景、正文没写发色服装，出图就会飘。**人物外观档案**就是为这件事准备的：为角色记一次外观描写，之后自动带上。

入口：配图面板顶栏右上角的 📇 图标。设置窗与档案管理窗都是独立的，改动**即时落盘**——不走小剧场的设置对话框（那里的改动要等「保存所有配置」，而配图面板是另一个界面，中间那段时间会读到旧值）。

每条档案包含名称、触发词、外观描写与可选的**角色卡绑定**。

**归属**：主列表是全局的，每条可以选择绑定一张角色卡。绑定用的是角色卡身份（基于头像文件名），所以进这个角色的任何聊天都必中。

**匹配**：绑定命中优先；没绑定的（或绑定没命中的）按触发词在**本轮正文**里匹配。触发词至少两个字符——单字几乎会命中任何正文。单次最多自动带入 4 条；档案内容与模型输出无关，只是喂给 LLM 的素材。

**勾选与手改**：命中的档案会自动填进「人物资料」文本框并预勾选，面板里可以随时增删。文本框归你所有——取消勾选时，只有当那一块仍是原样时才移除；你若已经在块内改过，就只取消勾选、不动文本。手打的内容永远不会被覆盖。

**从当前角色卡导入**：读的是当前打开那张卡的描述原文（不跑宏展开），导入后可以继续精简，并自动绑定该卡。

**从当前用户设定导入**：读的是当前生效的 Persona 正文（同样不跑宏展开），名称取 `{{user}}`，触发词写成这个名字，**不绑定角色卡**——用户设定不属于任何一张卡，绑上去会在别的角色的聊天里也被强行带入。想让它在某个角色那儿必中，导入后自己在下拉里选一张卡即可。名字短于两个字符时触发词会被规范化剔除，界面会提示你手动补一个。

**群聊**：群聊里没有单一角色卡，绑定不会生效（`{{char}}` 不指向具体成员）。请用触发词匹配，或到面板里手动勾选。一对一里绑定的档案不会跟着角色进群。

> 这与 Cosmos Vision 自己的「人物配置」是两套东西：那套存在对方私有设置里、且 `generateImage` 完全不引用它，小剧场读不到也影响不了。这里是插件自己的档案。

## 选景预设

送进选景模型的消息由**预设**决定。入口：配图面板顶栏右上角 ⚙️。改动**即时落盘**，没有保存按钮。

**没有内置预设**——预设一律由你「导入」或「新建」。第一次打开时设置窗会直接给出这两条出路，「分析画面」在没预设时会明确告诉你还没有配置。

- 一个**预设**是一串**条目**；每条有名称、消息角色（system / user / assistant）、启用开关和内容。条目按顺序拼成消息，顺序可拖拽调整。**条目默认折叠成一行的摘要**（名称 · 角色 · 是否停用），点行首的三角展开编辑；新建的条目会直接展开。
- **新建预设**直接给你一份可用的默认配置。
- **导入预设**认两种文件：SillyTavern 的 Chat Completion 预设，以及本插件导出的选景预设（两者导出形状一致）。导入时会**丢弃上下文注入类条目**（`chatHistory`、`worldInfoBefore`、`main` 之类）并提示跳过了几条——那些条目的语义是「运行时把当前聊天塞进来」，选景这条链路不能有。同名导入会覆盖原预设。
- 「导出」产出标准 Chat Completion 预设，既能回灌本插件，也能直接给酒馆或小剧场用。

### 托管条目

无论是导入还是新建，末尾都会自动补上小剧场自己的那四条（界面上带 ↺ 标记）：

| 条目 | 作用 |
|---|---|
| 选景要求 | 定义选景任务与排除条件 |
| 生图提示词规范 | 图源无关的提示词写法（Tag 与自然语言的分工、多角色绑定与指代、抽象描述限制） |
| 素材（user 角色） | 用占位符把正文与参考资料带进消息 |
| 输出格式 | JSON 契约：`summary`（中文画面描述）+ `sourceExcerpt`（逐字原文摘录）+ `positivePrompt`（英文生图提示词） |

**为什么要补**：一份酒馆预设压根不知道小剧场要怎么选景，补完它才真能用。导入后原来的条目排在前、托管条目排在后。

**输出格式为什么压在最末**：末位指令的服从度最高，而 JSON 能不能解析是整个链路最不能出错的一环——解析失败这一次选景就白花钱了。

画哪一家的语法、权重、质量词与负向词由下游的 Cosmos Vision 负责，所以这里只有**一份图源无关的规范**，不再按图源分条。

托管条目**可改写、可停用、可排序，但不能删**；改坏了用该条目上的 ↺ 还原默认内容（只还原内容，不动你的启用状态与排序）。

### 素材占位符

素材靠占位符进入提示词，可用的只有四个：

| 占位符 | 内容 |
|---|---|
| `{{theater_text}}` | 本轮小剧场正文 |
| `{{participants}}` | 面板里填的「人物资料」（人物外观档案也会自动填到这里） |
| `{{special_request}}` | 面板里填的「想画什么」 |
| `{{previous_scenes}}` | 「换个画面」时此前选过的画面摘要 |

后三个展开时会**带上标题**（如 `【人物资料】`）；值为空时整行消失，不会留下孤立的标题行。

**预设里必须恰好有一条启用条目包含 `{{theater_text}}`。** 缺了它正文不会被送进模型，选景会在发起请求**之前**报错——不会出现「花了钱却拿到一份没读正文的选景」。重复出现在多条启用条目里同样会拦下，避免十万字正文被发两遍。

### 变量宏

**STscript 变量宏会生效**：`{{setvar::名::值}}`、`{{getvar::名}}`、`{{addvar::}}`、`{{incvar::}}`、`{{decvar::}}` 及其 global 版共 10 个。这是导入的预设能用起来的前提——很多预设拿变量当「组装草稿纸」：前段条目逐条 `setvar` 写入各命名块，后段条目再 `getvar` 取回来拼装，同一个变量还可能有多条互斥候选（三种文风各一条），靠启用/停用挑一条。

- 变量**跨条目共享**，按条目顺序求值，所以前面的 `setvar` 对后面的 `getvar` 可见；停用的条目不执行它的 `setvar`。
- 整次选景共用一个**沙箱**：求值期间变量真的读写（展开结果与在酒馆里跑这份预设一致），选景一结束立刻**还原**，不写进你的聊天存档。整条只剩 `setvar` 的条目求值后为空，不会变成一条消息。
- 求值只作用于**预设作者写的文本**。素材（正文、人物资料）里字面写着的 `{{getvar::x}}` 不会被求值——素材永远是惰性文本。

**其余宏一律不展开**：`{{char}}`、`{{user}}`、`{{persona}}`、`{{description}}`、`{{random::}}`、`{{//注释}}`、`{{trim}}` 都会原样留在文本里。这是刻意的：那些宏读的是**当前聊天**，在这里展开就意味着在 B 聊天给 A 的收藏配图时会把 B 的角色资料注进提示词。

⚠️ **但变量本身也读当前聊天。** `{{getvar::x}}` 取的是**当前聊天**的变量。预设若读一个它自己没 `setvar` 过的变量，或者写这个变量的候选条目全被停用，取值就来自当前聊天——此时在 B 聊天给 A 的收藏配图，拿到的是 B 的值。**选景预设最好只读自己写过的变量。**

### 旧规范的迁移

升级前那份「选景提示词规范」如果你改过，会被自动转成一份名为「我的选景规范」的预设并设为当前使用，同时补上托管条目；没改过就直接进入「导入 / 新建」引导。迁移完成后旧的设置键会被删除。

## 保存语义

- 生成任务固定绑定发起时的正文快照，之后翻页、切聊天不会改变任务归属。
- 新的生成 ID 或正文修改会得到独立配图记录；分支中继承的同一生成结果共享原来的配图候选。
- **一次生成返回的多张图全部存为候选**，自动采用第一张。单次最多保存 8 张，超出部分丢弃并在状态栏说明。
- 主界面把当前采用图放在正文开头，与正文一同渲染。图片与提示词不会加入续写的正文输入。
- 收藏时将各轮当前采用图的元数据一起归档。收藏持有自己的采用图快照，之后可在收藏页单独换图。
- 生成成功后立即保存到酒馆用户文件。保存失败保留本次图片，使用「重试保存」即可，不再次请求生图；在同一页面关闭并重新打开面板也能继续保存。
- 关闭面板不中断选景与生图：任务在后台继续跑，完成后照常保存并成为当前配图，重新打开同一场景可以接着看进度、取消等待或查看结果。面板不在时任务结束会给一条提示。刷新页面会丢弃进行中的任务，所以刷新前应等结果落库或先取消。
- 「暂不展示配图」只移除当前展示选择。不自动删除已保存的图片文件，防止影响收藏或其他引用。
- 「导出图文 HTML」及收藏菜单中的「导出 HTML（含配图）」内嵌图片；完整插件备份也携带图片与记录，恢复时重新上传并改写路径。

## 进度与取消

- 选景阶段显示「正在通读正文、选择画面…」；生图阶段在 ComfyUI 下按步数显示百分比，NovelAI 流式会显示过程图（仅供预览，与「已生成待保存」是两种状态）。
- NovelAI 非流式没有中间进度，只显示「正在生成图片…」。
- 配图任务使用自己的取消控制器，与主聊天生成互不影响：取消配图不会中断正在跑的演绎，取消演绎也不会中断配图。
- 「取消等待」只解除本地等待。走 ST 主连接时底层请求不会被真正中断（连接层不向 `ChatCompletionService` 传信号），后端可能仍在计算；界面的措辞已如实反映这一点。

## 对接约定

Cosmos Vision 提供的是薄接口，`window.CosmosVision` 上只有：

```js
{
  version: string,                 // Cosmos 插件版本号，不用于兼容性判断
  generateImage({ prompts: { positivePrompt, negativePrompt, characterPrompts }, requestId?, signal?, onProgress?, onStreamPreview? })
    -> { requestId, imageBlobs: Blob[], prompts }
}
```

- 就绪事件为 `cosmos-vision:api-ready`。
- 没有 `getCapabilities`：图源可用性、模型标识、长度与张数上限都无从查询，只能等调用报错再转述。
- `prompts` 是**核心内容提示词**，Cosmos 会把它插进用户预设模板，再追加质量词、前置 UC 词与 LoRA 触发词。返回的 `prompts` 是合并前的核心值。
- 返回的 `imageBlobs` 是裸 Blob，**没有**类型与尺寸，需要自行嗅探与解析头部。
- `characterPrompts` 只对 NovelAI V4/V4.5/V5 生效，ComfyUI 下会被忽略（面板中的位置设置同理）。

客户端分层：选景 `src/core/illustrationScene.js`；选景预设 `src/core/illustrationPresets.js`（`prompt_order` 合并共用 `src/core/promptOrder.js`）；STscript 变量宏与变量沙箱 `src/core/stVariables.js`（主提示词构建共用同一份）；生图适配 `src/core/cosmosVisionBridge.js`；图片字节解析 `src/core/imageBytes.js`；容错 JSON 提取 `src/core/llmJson.js`；外观档案 `src/core/characterProfiles.js`；DTO 与校验 `src/core/illustrationData.js`；图片与记录保存 `src/core/illustrationStore.js`；备份/导出 `src/core/illustrationPortability.js`；交互面板 `src/ui/illustrationWindow.js`；配图设置窗 `src/ui/illustrationSettingsWindow.js`；档案管理窗 `src/ui/characterProfileWindow.js`。

设置只记录 `illustration_index` 的小型文件指针。正文、角色设定和图片 base64 不写入该索引。图片文件为 `/user/files/titania-illustration-*.png|jpg|webp`，场景记录为 `/user/files/titania-scene-*.json`。

`docs/Cosmos-Vision-公开接口需求-v1.md` 与 `docs/cosmos-vision-public-api-v1.d.ts` 是历史约定，对方并未按它实现，仅供追溯。

## 数据版本

草稿为 `version: 2`，含 `backend: 'cosmos'` 与可选的 `scene.sourceExcerpt`。**读时兼容 v1**：升级前存下的记录、收藏内嵌配图与备份包都会自动迁移，渲染与导出不受影响。

注意：v2 草稿不再有 `imageSource`/`model`，**旧版插件无法读取新记录**，即从新版本回退到旧版本后配图数据不可用。完整备份宣传的「退回上个版本就能原样恢复」对配图不成立。

## 已知限制

- **ComfyUI 会绑定当前角色/用户头像。** 若 Cosmos 当前工作流把图片绑定设成「当前角色头像」或「当前用户头像」，那么为 A 聊天配图而人停留在 B 聊天时，会上传 **B 聊天**的头像作为参考图，画错人且构成跨聊天数据外泄。小剧场读不到 Cosmos 的私有设置，无法探测也无法阻止。**建议把工作流的图片绑定改成本地上传。**
- **用户不再是「所见即所发」。** 面板里编辑的是核心内容提示词，最终请求还会被 Cosmos 追加预设、质量词、UC 词与 LoRA 触发词。
- **选景依赖插件自己的 API 方案**，默认跟随小剧场当前激活方案。Cosmos 的 Prompt LLM 配置不再参与配图。
