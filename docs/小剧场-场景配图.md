# 小剧场场景配图

## 使用入口

- 新版主界面：正文右侧图片图标。
- 经典主界面：内容工具中的「场景配图」。
- 收藏阅读页：顶栏图片图标。分组收藏可在面板中选择具体一轮。

默认使用当前一轮的完整正文。可以在「正文与人物资料」中调整本次素材、补充人物外观；这些信息只用于配图，不修改剧场正文或酒馆角色卡。

**入口随时可点。** 当前这一轮还不能配图时（正在生成 / 这一轮失败 / 全新还没演绎过），面板照常打开，只是没有素材可用：状态行说明是哪种情况，「分析画面 / 换个画面 / 生成图片」禁用，顶栏的人物外观档案与设置照常可用。等这一轮写完再点一次即可 —— 不会弹一句「请先选择一段已完成的内容」把点击挡回去。

**配图面板、配图设置窗与档案管理窗的顶栏都有一个问号**，所有「永远成立」的说明都收在那里（怎么用、提示词只写内容、后端怎么选、占位符是什么、档案何时生效）。界面本身只留操作。**条件性的提示不进去** —— 「这个后端不支持人物位置」「预设校验失败」「保存失败请重试」只在该出现的那一刻出现，留在各自位置上。

## 流程与分工

配图分两步，由两个不同的执行者完成：

1. **分析画面**（本插件的 API 方案）：通读正文，选出一个适合画成单幅插图的瞬间，产出中文画面描述、原文摘录与英文生图提示词。送进模型的消息由**选景预设**决定，见下一节。
2. **生成图片**（外部生图插件）：把小剧场给出的提示词交给**当前选中的生图后端**，由它按自己的配置出图。

点击「分析画面」后预览中文画面描述和原文摘录（摘录由模型从正文里逐字复制，对不上就丢掉那一行——画面本身照常留用），展开后可以编辑全局正负提示词、人物提示词与位置。点击「换个画面」重新运行选景（会把此前选过的画面作为排除参考）；再次点击「生成图片」沿用当前提示词，重新请求图片。

**「换个画面」是要求，不是保证。** 排除表送进「已经选过的画面」那块素材，而「选景要求」里明确写了必须换一幅——只把它当素材标题时，模型会当成上下文读，被同一份条目里「选唯一一个最适合的瞬间」压过去，于是原样再选一次。仍有两点限制：

- 正文里确实只有一个可落笔的瞬间时，模型允许复用同一幅。真复用了，面板会明说一句（而不是让你对着两个一样的摘要猜是不是坏了），并指向「本次额外要求」——那是唯一能压过选景要求的入口。
- 排除表只覆盖**本插件记得的画面**：本次会话里选过的，以及记录里当前采用的那一幅。刷新页面后前者会丢，后者由记录补种，所以除非刷新前选过好几幅又都没保存，否则不会漏。

**提示词只写「画面里有什么」。** 质量词、画师串、UC 词、画风预设、LoRA 触发词与画幅采样器一律由生图后端追加，小剧场不写也不该写——重复填写会导致叠加。因此面板里显示的提示词**不等于**最终发给后端的内容。

**画面张数与来源不可控。** 由后端自己的设置决定：出图张数、图源与模型都归它管。小剧场无法指定，也不会替你切换。

接口未安装、就绪状态变化或旧版接口时，面板显示具体状态（区分「未安装」「旧版接口」「未配置」「已连接」），也可以点击「重新检测」。已保存图片的浏览、采用、下载与导出，以及点图库缩略图开灯箱看大图，都不依赖任何生图后端在线。

## 自动配图（可选）

**默认关闭。** 开关在「场景配图设置」里（生图后端下方）。打开之后，每次**「单次演绎」或「重演」**完成会自动跑一遍上面那两步 —— 选景、生图、保存，不需要你在面板上点任何东西。

**触发范围是刻意的：**

| 入口 | 会不会自动配 |
|---|---|
| 单次演绎 | **会** |
| 重演（同一条生成路径，也是新的一轮） | **会** |
| 主动续写 | 不会 |
| 队列生成（一次排 N 个剧本） | 不会 |
| ST 事件触发的「自动演绎」 | 不会 |
| 预览 | 不会 |

后三者都是**无人看着的连续生成**，跟着配图会一口气烧掉多张图的额度，所以一律不触发。判据是生成来源（`generationSource === "manual"`），不是「有没有开静音」—— 将来给某条静音路径补上显式来源，判据仍然成立。

**成本要说在前面**：每一轮自动配图都是一次真实的选景调用 + 一次真实的生图，与手动点「分析画面」「生成图片」完全等价（选景返回坏格式时最多重试一次，即最多两次选景）。

**跑完只有一条提示**，不弹灯箱、不打断阅读，正文与内容区依旧不出现任何配图元素 —— 图在配图面板的图库里。跑不起来时（后端没装好、没有选景预设、选景失败）也各有一条提示说明原因与去处，不会静默。

**面板会接管正在跑的自动任务。** 自动配图要跑十几秒到一分钟，这期间打开配图面板，你会看到它的进度（状态行写着「自动配图：正在…」）、按钮被禁用，也可以在那里点「取消等待」。这不是装饰：没有它，用户看着空图库点「分析画面」就是同一轮付两次钱。

**一次只跑一个。** 上一张还在配的时候又完成一轮（例如连着点两次单次演绎），那一轮会跳过并提示一句，不会并发花两份钱。

## 生图后端

入口：配图面板顶栏右上角 ⚙️（「场景配图设置」最上方）。**这里是全局默认，改动即时落盘**；配图面板只读它，顶栏下方显示它的就绪状态。

| 后端 | 出处 | 特点 |
|---|---|---|
| **Cosmos Vision** | `window.CosmosVision` | 一次可出多张；人物位置可用。画幅、画风与质量词在它那边配置。 |
| **柏宝绘** | `globalThis.STBaiBaiImage` | 一次出一张；**人物位置固定在画面中心**；**NovelAI 下不使用这里填的负向提示词**（用它自己渠道的负向词）。 |
| **智绘姬（st-chatu8）** | 酒馆的 `eventSource`（两条事件） | 一次出一张；**不支持分人物提示词与人物位置**；**用哪个渠道由它自己的「主要设置」决定**（SD / NovelAI / ComfyUI / Banana / RunningHub），密钥、工作流、替换词、质量词全在它那边配。**没有取消接口**：这里的「取消等待」只是不再等，它那边会照常算完。 |

智绘姬这条走的是**它的公开事件接口**（作者教程「前端接入」）：请求 `generate-image-request`、响应 `generate-image-response`，两条都跑在**酒馆自己的 `eventSource`** 上 —— 前端的 `eventEmit` / `eventOn` 只是它的转发壳（JS-Slash-Runner 的 `src/function/event.ts` 里 `_eventEmit` 就是 `await eventSource.emit(...)`），所以本插件不依赖前端助手。接单的是它当前选中的那个渠道，所以这里不需要知道用户用哪一家。

选中的后端决定**新选出的草稿**交给谁。草稿落盘时把后端一起记下来，所以：

- **换后端重画不用重新选景** —— 提示词只有内容、没有风格，是后端无关的。改了设置后点「重新生成」会用当前后端重画这一份提示词。
- **后端卸载了，旧记录照样能看** —— 探测只发生在出图时。浏览、采用、下载、导出与备份都不需要后端在线，只有再点「生成图片」才会报「未检测到」。

### 后端做不到的事，界面会说明而不是静默丢弃

选中的后端能力不够时，配图面板会把对不上的控件收起来或加一句提示。人物位置的**数值仍留在草稿里**，切回支持它的后端就还在。

- 人物位置：后端固定居中的（柏宝绘），X / Y 输入收起并提示。
- 全局负向提示词：NovelAI 下后端不接受它的（柏宝绘），负面框旁提示「这里填写的不会生效」。
- 分人物提示词：后端整块不支持的（柏宝绘 + ComfyUI），整个区域收起。若你填了而这次**没被用上**，出图后会明说一句——否则你只会以为画面画错了。**小剧场刻意不降级**把角色拼进正向提示词，那会画出多份重叠躯干。
- 画幅：只有支持指定画幅的后端才显示这个下拉；**它是会话级的，不写进草稿**，刷新页面后重开会回到「由后端决定」。

### 加一个新后端

后端是**插件式**的：新增一个适配文件 + 在注册表里加一项，选景、存储、界面主链路都不用动。

- 注册表：`src/core/illustrationBackends/registry.js`（表、当前后端的设置项、就绪事件订阅）
- 适配器：`src/core/illustrationBackends/*.js`，每个导出一个对象：`{ id, label, readyEvents, probe(), generate() }`
  - `probe()` 同步且不抛，返回 `{ ready, status, reason, capabilities, detail }`。`status` 取 `missing | legacy | unsupported | not_configured | ready`。
  - `generate()` 只回**原始字节**（`{ blobs, seed?, applied? }`），嗅探、校验、落库由门面 `cosmosVisionBridge.js` 统一做，所有后端共用一条路径。
  - `capabilities` 决定界面收起哪些控件：`characterPrompts / characterPositions / characterNegative / negativePrompt / size / batch / streamPreview`。
- ⚠ **`illustrationData.js` 的 `ILLUSTRATION_BACKEND_IDS` 必须同步加**：那是读路径的校验白名单，漏了会出现「选得出、存得下、读不回」。有测试盯着两份清单一致。
- ⚠ **id 只增不删**：删掉一个 id 会让所有存着该 id 的旧记录在读取时抛错，整条场景记录失效（画廊与导出一起坏）。要停用一个后端就把它留在列表里、由适配器报「未安装」。
- 适配器**不 import 酒馆宿主模块**，只经 `globalThis` 拿对方的东西（`window.CosmosVision` / `globalThis.STBaiBaiImage` / `SillyTavern.getContext().eventSource`）—— 这样测试夹具能直接加载它们。智绘姬那份就是范例：它的全部状态都在 `extension_settings["st-chatu8"]` 里，事件总线则取 `getContext().eventSource`。

## 人物外观档案

选景时只有一份「人物资料」可用，默认空着。角色换个场景、正文没写发色服装，出图就会飘。**人物外观档案**就是为这件事准备的：为角色记一次外观描写，之后自动带上。

入口：配图面板顶栏右上角的 📇 图标。设置窗与档案管理窗都是独立的，改动**即时落盘**——不走小剧场的设置对话框（那里的改动要等「保存所有配置」，而配图面板是另一个界面，中间那段时间会读到旧值）。

每条档案包含名称、触发词、外观描写与**归属**。外观描写**不截断**——写多长就带多长：砍掉的往往是末尾那些更具体的特征（耳饰、纹样），而文本框里仍是完整的，画错了也无从察觉。送不下是模型上下文的事，由你在预设里自己权衡。

### 两个页签与小卡片网格

管理窗顶上是**一分为二的页签栏：左边「角色档案」、右边「用户档案」**，各带一个条数。进窗默认停在角色档案，点另一边才切过去——**两组不同时铺在一屏里**，这是为了不再互相挤。下面是当前这一组的紧凑小卡片网格：点哪张哪张就地展开成整行的编辑区，再点收起。原先每条都摊开成通栏大卡（一条近 250px 高）且两组堆在一起，档案一多就只能靠滚动找。

**归属记在档案里，不是靠「绑没绑卡」推出来的。** 没绑卡的角色档案（靠触发词匹配的）仍然属于角色档案。这条区分由编辑区里的「归属与绑定」下拉控制，三选一：

| 选项 | 结果 |
|---|---|
| 不绑定角色卡 | 角色档案，靠触发词匹配 |
| 用户本人（`{{user}}`） | 用户档案，恒定不绑卡 |
| 某张角色卡 | 角色档案，绑定该卡（进这个角色的任何聊天都必中） |

归属与绑定是互斥的：选了「用户本人」就会解绑，这不是界面上的限制而是模型层的规则——绑着卡的用户档案在下拉框里既表达不出来、也退不回去。**改归属等于把这条档案搬到另一个页签**，所以状态栏会明说一句「已移到用户档案」，否则看着就像它被删了。两条导入路径同理：会把页签切到新档案所在的那一边并展开它。

**拖动排序只能在同组内进行**（页签已经把另一组挡在画面外，想拖也没有落点）。分组只是**展示**上的分区：底层仍是一条扁平列表，顺序决定「最多自动带入 4 条」取谁。所以组内拖动**只重排该组占用的位置**，另一组的条目的绝对位置一个都不动——否则角色档案一旦超过 4 条，用户档案就会永远被挤出上限、再也不自动带入，而这个后果在页签界面里完全看不见。

**升级**：v1 的老记录没有归属字段，一律落成**角色档案**。旧数据里没有可靠信号能区分「用户设定导入的」与「手写的、没绑卡的」（群聊里从角色卡导入同样不绑卡，触发词恰好等于档案名也是任何新档案填完名字的状态），猜就会误判。归属不参与匹配，判错只是分组位置不对、匹配行为与从前完全一致，自己用下拉改一下即可。

**匹配**：绑定命中优先；没绑定的（或绑定没命中的）按触发词在**本轮正文**里匹配。触发词至少两个字符——单字几乎会命中任何正文。单次最多自动带入 4 条；档案内容与模型输出无关，只是喂给 LLM 的素材。归属**不参与**匹配，只影响分组展示与上面的下拉。

**触发词默认跟着档案名走**：新建档案后填个名字，触发词就自动填成这个名字，不必再手打一遍；之后改名字它也跟着改。一旦你自己写过触发词（例如加上别名「阿离，小离」），它就归你了，改名不再覆盖——与「人物资料」那条「手打的永不被覆盖」是同一原则。名字短于两个字符时触发词留空（而不是填一个会被规范化裁掉的值），需要你自己补一个。

**勾选与手改**：命中的档案会自动填进「人物资料」文本框并预勾选，面板里可以随时增删。文本框归你所有——取消勾选时，只有当那一块仍是原样时才移除；你若已经在块内改过，就只取消勾选、不动文本。手打的内容永远不会被覆盖。

**从当前角色卡导入**：读的是当前打开那张卡的描述原文（不跑宏展开），导入后可以继续精简，并自动绑定该卡。归入**角色档案**，导入后自动展开。

**从当前用户设定导入**：读的是当前生效的 Persona 正文（同样不跑宏展开），名称取 `{{user}}`，触发词写成这个名字，归入**用户档案**且不绑卡——用户设定不属于任何一张卡，绑上去会在别的角色的聊天里也被强行带入。想让它在某个角色那儿必中，导入后自己在「归属与绑定」里选一张卡即可（那会把它改成角色档案）。名字短于两个字符时触发词会被规范化剔除，界面会提示你手动补一个。导入后自动展开。

**群聊**：群聊里没有单一角色卡，绑定不会生效（`{{char}}` 不指向具体成员）。请用触发词匹配，或到面板里手动勾选。一对一里绑定的档案不会跟着角色进群。

> 这与 Cosmos Vision 自己的「人物配置」是两套东西：那套存在对方私有设置里、且 `generateImage` 完全不引用它，小剧场读不到也影响不了。这里是插件自己的档案。

## 选景预设

送进选景模型的消息由**预设**决定。入口：配图面板顶栏右上角 ⚙️。改动**即时落盘**，没有保存按钮。

**没有内置预设**——预设一律由你「导入」或「新建」。第一次打开时设置窗会直接给出这两条出路，「分析画面」在没预设时会明确告诉你还没有配置。

- 一个**预设**是一串**条目**；每条有名称、消息角色（system / user / assistant）、启用开关和内容。条目按顺序拼成消息，顺序可拖拽调整。**条目默认折叠成一行的摘要**（名称 · 角色 · 是否停用），点行首的三角展开编辑；新建的条目会直接展开。
- **新建预设**直接给你一份可用的默认配置。
- **导入预设**认两种文件：SillyTavern 的 Chat Completion 预设，以及本插件导出的选景预设（两者导出形状一致）。导入时会**丢弃上下文注入类条目**（`chatHistory`、`worldInfoBefore`、`main` 之类）并提示跳过了几条——那些条目的语义是「运行时把当前聊天塞进来」，选景这条链路不能有。同名导入会覆盖原预设。
- 「导出」产出标准 Chat Completion 预设，既能回灌本插件，也能直接给酒馆或小剧场用。

### 托管条目

无论是导入还是新建，末尾都会自动补上小剧场自己的那四条（界面上带 ↺ 标记）：

| 条目 | 作用 |
|---|---|
| 选景要求 | 定义选景任务与排除条件 |
| 生图提示词规范 | 图源无关的提示词写法：正面提示词固定为 **Tag 段 + 换行 + NL 段**，Tag 只写公共画面信息（人数、镜头、时间、环境、光影、简单构图与动作），角色外貌/服装/配饰/表情一律进各角色自己的连续 NL 描述，多角色分别建立指代后再写互动，抽象要求转译成可见事实，禁止 BREAK 与质量/风格词 |
| 素材（user 角色） | 用占位符把正文与参考资料带进消息 |
| 输出格式 | JSON 契约：`summary`（中文画面描述）+ `sourceExcerpt`（逐字原文摘录）+ `positivePrompt`（英文生图提示词） |

**为什么要补**：一份酒馆预设压根不知道小剧场要怎么选景，补完它才真能用。导入后原来的条目排在前、托管条目排在后。

**输出格式为什么压在最末**：末位指令的服从度最高，而 JSON 能不能解析是整个链路最不能出错的一环——解析失败这一次选景就白花钱了。

**`positivePrompt` 是两段，不是一行。** 规范要求 Tag 段在前、换行后接 NL 段，所以它里面有一个换行；「输出格式」里那条约束与它成对（改一处必须改另一处，否则模型同时收到「必须换行」与「必须一行」两条相反的指令）。模型在 JSON 里把它写成 `\n` 即可；真写了裸换行也会被容错解析修回来（`llmJson.js` 会把字符串字面量里未转义的换行转义掉）。面板的提示词框本来就是多行文本框，人工改动不受影响。

画哪一家的语法、权重、质量词与负向词由下游的 Cosmos Vision 负责，所以这里只有**一份图源无关的规范**，不再按图源分条。

托管条目**可改写、可停用、可排序，但不能删**；改坏了用该条目上的 ↺ 还原默认内容（只还原内容，不动你的启用状态与排序）。

⚠️ **升级不会自动刷新托管条目的内容。** 预设存的是你那份副本，插件只在缺条目时补一份新的——所以默认文案改了（例如「选景要求」新增「换个画面必须换一幅」那条约束），**已有预设不会跟着变**，需要你点一下那条的 ↺。这是刻意的：分不清「没改过」和「改成了别的样子」，自动覆盖会静默毁掉用户自己写的版本。

### 素材占位符

素材靠占位符进入提示词，可用的只有四个：

| 占位符 | 内容 |
|---|---|
| `{{theater_text}}` | 本轮小剧场正文 |
| `{{participants}}` | 面板里填的「人物资料」（人物外观档案也会自动填到这里） |
| `{{special_request}}` | 面板里填的「想画什么」 |
| `{{previous_scenes}}` | 「换个画面」时此前选过的画面摘要 |

后三个展开时会**带上标题**（如 `【人物资料】`）；值为空时整行消失，不会留下孤立的标题行。

**预设里必须恰好有一条启用条目包含 `{{theater_text}}`。** 缺了它正文不会被送进模型，选景会在发起请求**之前**报错——不会出现「花了钱却拿到一份没读正文的选景」。重复出现在多条启用条目里同样会拦下，避免十万字正文被发两遍。

### 变量宏

**STscript 变量宏会生效**：`{{setvar::名::值}}`、`{{getvar::名}}`、`{{addvar::}}`、`{{incvar::}}`、`{{decvar::}}` 及其 global 版共 10 个。这是导入的预设能用起来的前提——很多预设拿变量当「组装草稿纸」：前段条目逐条 `setvar` 写入各命名块，后段条目再 `getvar` 取回来拼装，同一个变量还可能有多条互斥候选（三种文风各一条），靠启用/停用挑一条。

- 变量**跨条目共享**，按条目顺序求值，所以前面的 `setvar` 对后面的 `getvar` 可见；停用的条目不执行它的 `setvar`。
- 整次选景共用一个**沙箱**：求值期间变量真的读写（展开结果与在酒馆里跑这份预设一致），选景一结束立刻**还原**，不写进你的聊天存档。整条只剩 `setvar` 的条目求值后为空，不会变成一条消息。
- 求值只作用于**预设作者写的文本**。素材（正文、人物资料）里字面写着的 `{{getvar::x}}` 不会被求值——素材永远是惰性文本。

**其余宏一律不展开**：`{{char}}`、`{{user}}`、`{{persona}}`、`{{description}}`、`{{random::}}`、`{{//注释}}`、`{{trim}}` 都会原样留在文本里。这是刻意的：那些宏读的是**当前聊天**，在这里展开就意味着在 B 聊天给 A 的收藏配图时会把 B 的角色资料注进提示词。

⚠️ **但变量本身也读当前聊天。** `{{getvar::x}}` 取的是**当前聊天**的变量。预设若读一个它自己没 `setvar` 过的变量，或者写这个变量的候选条目全被停用，取值就来自当前聊天——此时在 B 聊天给 A 的收藏配图，拿到的是 B 的值。**选景预设最好只读自己写过的变量。**

### 旧规范的迁移

升级前那份「选景提示词规范」如果你改过，会被自动转成一份名为「我的选景规范」的预设并设为当前使用，同时补上托管条目；没改过就直接进入「导入 / 新建」引导。迁移完成后旧的设置键会被删除。

## 保存语义

- 生成任务固定绑定发起时的正文快照，之后翻页、切聊天不会改变任务归属。
- 新的生成 ID 或正文修改会得到独立配图记录；分支中继承的同一生成结果共享原来的配图候选。
- **一次生成返回的多张图全部存为候选**，自动采用第一张。单次最多保存 8 张，超出部分丢弃并在状态栏说明。
- **主界面不把图插进正文，内容区里也没有任何常驻的配图元素。** 正文往往是自带底色的卡片，插图在开头只会把它顶出屏幕；所以图片只在配图面板里存在，采用与否只影响正文之后拼出来的收藏与导出。图片与提示词都不会加入续写的正文输入。
  - 看大图的唯一入口是**图库里的缩略图**：点它开**灯箱**，看的正是你点的那一张（以前这里是个 `target="_blank"` 的链接，点开是浏览器新标签页）。
  - 灯箱铺满视口，Esc、点遮罩、关闭按钮三路都能关；一次只放一张，**不能左右翻候选**，也**不会**在生成完成后自动弹出。它挂在面板自己的 root 里，所以面板一关它跟着消失。
  - 长竖图在灯箱里保持原尺寸纵向滚动，横图缩到宽度内。
- **内容区那个按钮已删除**（5.4 起曾经有一个底部中间的图标按钮：有图时点开灯箱，选景/生图/保存中显示转圈，读取失败显示警告）。删掉之后面板关着时后台任务的反馈只剩完成/失败那一条 toastr —— 想看进度就把面板打开。
- **收藏阅读页与导出的 HTML 仍是图文一体**——图接在正文之后，与主界面的处理刻意不同：导出的东西应当自包含。
- 收藏时将各轮当前采用图的元数据一起归档。收藏持有自己的采用图快照，之后可在收藏页单独换图。
- 生成成功后立即保存到酒馆用户文件。保存失败保留本次图片，使用「重试保存」即可，不再次请求生图；在同一页面关闭并重新打开面板也能继续保存。
- 关闭面板不中断选景与生图：任务在后台继续跑，完成后照常保存并成为当前配图，重新打开同一场景可以接着看进度、取消等待或查看结果。面板不在时任务结束会给一条提示。刷新页面会丢弃进行中的任务，所以刷新前应等结果落库或先取消。
- 「暂不展示配图」只移除当前展示选择——收藏与导出里不再带图。这个动作只留在配图面板图库里，灯箱不提供。它不删除任何文件。
- **删除配图**：图库里每张卡片底部有一个删除按钮；也可以点「管理」进入多选，勾选后批量删除。**删除不可撤销，没有回收站**，会先弹确认框写明后果。
  - 删除会移除场景记录里的这一张，**并且**删除磁盘上的图片文件——但同一个文件若仍被**任何其他场景记录或任何收藏**引用，则只移除记录、**保留文件**（收藏页那张图会照常显示）。确认框会写明有几张因被收藏引用而保留。
  - 被删的若是当前采用图，会自动改用剩余的第一张；一张都不剩就变成「无配图」。
  - 从收藏页打开面板时删除，该收藏里那张快照会一并更新或清除，所以重开面板**不会**让图"复活"。
- 「导出图文 HTML」及收藏菜单中的「导出 HTML（含配图）」内嵌图片；完整插件备份也携带图片与记录，恢复时重新上传并改写路径。

## 进度与取消

- 选景阶段显示「正在通读正文、选择画面…」；生图阶段在 ComfyUI 下按步数显示百分比，NovelAI 流式会显示过程图（仅供预览，与「已生成待保存」是两种状态）。
- NovelAI 非流式没有中间进度，只显示「正在生成图片…」。
- 配图任务使用自己的取消控制器，与主聊天生成互不影响：取消配图不会中断正在跑的演绎，取消演绎也不会中断配图。
- 「取消等待」只解除本地等待。走 ST 主连接时底层请求不会被真正中断（连接层不向 `ChatCompletionService` 传信号），后端可能仍在计算；界面的措辞已如实反映这一点。
- **自动配图没有自己的取消入口**（内容区那个按钮在 5.4 删掉了），但它在跑的时候打开配图面板就能接管并取消 —— 面板的那个「取消等待」abort 的就是自动任务的控制器。面板关着时确实停不下来，重开面板即可。
- 落盘阶段（正在保存）不显示「取消等待」：图已经生成并付过费了，这时取消只会把它丢掉。面板与自动配图共用这一条语义。

## 对接约定

两个后端提供的都是薄接口，各自只有出图这一个能力。

**Cosmos Vision** —— `window.CosmosVision`：

```js
{
  version: string,                 // Cosmos 插件版本号，不用于兼容性判断
  generateImage({ prompts: { positivePrompt, negativePrompt, characterPrompts }, requestId?, signal?, onProgress?, onStreamPreview? })
    -> { requestId, imageBlobs: Blob[], prompts }
}
```

- 就绪事件为 `cosmos-vision:api-ready`。按**方法存在性**判断可用性，不看版本号（拿对方插件版本做兼容判断会随它发版误判）。
- 没有 `getCapabilities`：图源可用性、模型标识、长度与张数上限都无从查询，只能等调用报错再转述。因此适配器一律按「全支持」上报能力。
- `prompts` 是**核心内容提示词**，Cosmos 会把它插进用户预设模板，再追加质量词、前置 UC 词与 LoRA 触发词。返回的 `prompts` 是合并前的核心值。
- 返回的 `imageBlobs` 是裸 Blob，**没有**类型与尺寸，需要自行嗅探与解析头部。
- `characterPrompts` 只对 NovelAI V4/V4.5/V5 生效，ComfyUI 下会被忽略（面板中的位置设置同理）。它没有查询接口，**这处不实探测不到**，界面仍会显示位置编辑器。

**柏宝绘** —— `globalThis.STBaiBaiImage`（API v1，文档见其仓库 `PUBLIC_API.md`）：

```js
{
  apiVersion: 1,                   // 公开数据结构的版本，与插件版本分开；只认 1
  getBackendStatus() -> { backend: 'nai'|'comfyui', configured, model, supportsCharacters, reason },
  generate({ prompt, nl?, negative?, characters?, size?, seed?, save?, character? }, { signal?, onProgress? })
    -> { dataUrl, format, path, seed, backend, charactersApplied }
}
```

- 就绪事件为 `st-baibai-image:ready` 与 `:changed`。**两个都订阅** —— 后者表示它在设置里改了后端配置。
- 回的是 **data URL 字符串**而不是 Blob，解码后并入同一条嗅探与校验路径（`dataUrlToBlob`）。
- **一次只出一张**，没有 count 参数。
- 人物位置由它**硬编码在画面中心**，调用方无法指定；`characters[].name` 只作标识、不进提示词，但**必须非空**（空名字的项会被它丢掉）。
- **NovelAI 下 `negative` 会被忽略**（用它自己渠道的负向词），只有 ComfyUI 会填进工作流。
- `characters` 在模型不支持时会被它**静默丢弃**，靠 `charactersApplied` 如实回报。
- 落盘一律传 **`save: false`**：它的默认是 `true`，会把图也存进它自己的图库；本插件的收藏、备份与图文导出都依赖自己的存储，不要两份。
- 错误按 **`error.code`** 分支（`aborted` / `not_configured` / `invalid_args` / `rate_limited` / `backend_error`），**绝不匹配 message 文案**（中文、会随版本改），也不用 `instanceof`（跨 bundle 失效）。
- ⚠ **不调用它的 `getCharacters()`**。它的角色库按「当前聊天」作用域，在 B 聊天给 A 的收藏配图时会返回 B 的角色——正是本插件跨聊天隔离铁律要挡的东西。人物外观只由本插件的 `character_profiles` 维护，有测试盯着这条不许破。

客户端分层：选景 `src/core/illustrationScene.js`；选景预设 `src/core/illustrationPresets.js`（`prompt_order` 合并共用 `src/core/promptOrder.js`）；STscript 变量宏与变量沙箱 `src/core/stVariables.js`（主提示词构建共用同一份）；生图分派门面与共用校验 `src/core/cosmosVisionBridge.js`；各后端适配 `src/core/illustrationBackends/`（`registry.js` 注册表、`cosmos.js`、`baibai.js`）；图片字节解析与 data URL 解码 `src/core/imageBytes.js`；容错 JSON 提取 `src/core/llmJson.js`；外观档案 `src/core/characterProfiles.js`；DTO 与校验 `src/core/illustrationData.js`；图片与记录保存 `src/core/illustrationStore.js`；**删除前的引用计数** `src/core/illustrationReferences.js`（场景侧遍历 `illustration_index`，收藏侧走 `favsStore`；它刻意放在两个 store 之上，因为 store 不能依赖 favsStore）；备份/导出 `src/core/illustrationPortability.js`（其中的路径提取器 `collectIllustrationPaths` 已上提到 `illustrationData.js`，与删除路径**共用同一份**，免得各写一套而漂移）；交互面板与它在主界面的入口 `src/ui/illustrationWindow.js`；**灯箱** `src/ui/illustrationLightbox.js`；**自动配图** `src/core/illustrationAuto.js`（`maybeAutoIllustrate` 由 api.js 的成功路径直接调用，另有 `shouldAutoIllustrate` 纯判据与 `getAutoIllustrationJob` 供面板接管）；配图设置窗 `src/ui/illustrationSettingsWindow.js`；档案管理窗 `src/ui/characterProfileWindow.js`。

客户端没有「任务进行态」的跨模块通道：曾经有一条 `illustrationActivity.js` 把面板的进行态推给内容区那个按钮，按钮删除后它没有消费者，已一并删除。后台任务的反馈只剩面板状态行（面板开着）与完成/失败 toastr（面板关着）。

唯一的例外是自动配图：`src/core/illustrationAuto.js` 暴露了一个 `getAutoIllustrationJob(sceneId)` 给面板**接管**正在跑的任务（显示进度、禁用按钮、可取消）。它刻意只查不推 —— 没有事件、没有订阅，因此不会退回成当年那条广播通道。

加面板、动灯箱时注意一条结构约束：**灯箱必须挂在配图面板自己的 root 里**。面板 root 是 `z-index: 20060` 的层叠上下文，灯箱作为它的后代必然盖在面板内容之上且随面板消失；挂到 `#t-overlay` 反而更糟（那个容器带 `isolation: isolate` + `z-index: 20000`，会把灯箱困在更低一层，整块藏在面板后面），挂 `.t-content-wrapper` 也不行（`transform: translateZ(0)` + `overflow: hidden` 会裁掉 `position: fixed` 的后代）。面板 root 带 `pointer-events: none`，所以灯箱在 CSS 里自己收回来。

设置只记录 `illustration_index` 的小型文件指针。正文、角色设定和图片 base64 不写入该索引。图片文件为 `/user/files/titania-illustration-*.png|jpg|webp`，场景记录为 `/user/files/titania-scene-*.json`。

`docs/Cosmos-Vision-公开接口需求-v1.md` 与 `docs/cosmos-vision-public-api-v1.d.ts` 是历史约定，对方并未按它实现，仅供追溯。

## 数据版本

草稿为 `version: 2`，含 `backend`（`'cosmos'` 或 `'baibai'`）与可选的 `scene.sourceExcerpt`。**读时兼容 v1**：升级前存下的记录、收藏内嵌配图与备份包都会自动迁移，渲染与导出不受影响。图片记录另有一个可选的 `seed`（后端报回来时才存，用于复现）。

人物外观档案为 `character_profiles.version: 2`（v1 加 `kind` 归属字段，读时迁移、只写一次）。`kind` 只影响分组展示，**不参与匹配**。

注意：v2 草稿不再有 `imageSource`/`model`，而且 `backend` 的白名单是**只增不删**的——加了柏宝绘之后，**比它旧的插件版本无法读取柏宝绘的配图记录**（会判成「配图记录损坏」）。从新版本回退到旧版本后，这部分配图数据不可用；完整备份宣传的「退回上个版本就能原样恢复」对配图不成立。

## 已知限制

- **柏宝绘：一次只出一张**，没有 count 参数，所以候选永远只有一个。想要多张就多点几次「生成图片」（每次都是一次真实计费）。
- **柏宝绘：人物位置固定在画面中心**，面板里的 X / Y 对它无效（切回 Cosmos 仍然有效，值一直留在草稿里）。
- **柏宝绘 + NovelAI：这里填的负向提示词不会被使用**，它用的是你在柏宝绘渠道里配的负向词。
- **柏宝绘 + ComfyUI：分人物提示词会被丢弃**（它的 `supportsCharacters` 只看模型，ComfyUI 恒为 false）。出图后状态栏会明说这次没用上。
- **画幅不落库**：面板里的画幅下拉是会话级的，刷新页面后重开会回到「由后端决定」，不会跟着记录复现。
- **智绘姬：一次只出一张，不支持分人物提示词与人物位置**（它的请求里只有一个 `prompt` 字段）。草稿里仍然留着那些值，切回 Cosmos 就能用；面板会把对不上的控件收起来。
- **智绘姬：画幅也由它决定**，它按自己渠道里配的宽高出图，面板上不出现画幅下拉。
- **智绘姬：banana 渠道不使用这里填的负向提示词**（它那条处理器不读 `negative_prompt`）；其余四个渠道会带上，且它自己的负向预设照常叠加。
- **智绘姬：没有取消接口**。在它那边出图的过程中点「取消等待」，只是这里不再等 —— 它仍会算完并计费，与走 ST 主连接时同一个口径。
- **智绘姬：它自己的替换词、质量词与缓存照常生效**。我们会把提示词原样交给它，它按自己的规则加工（那正是选它当后端的意义），并按提示词的 MD5 把结果进它自己的图片缓存。
- **智绘姬：界面不会自动发现它被启用。** 它没有「我准备好了」的广播（配置变化派发在 `document` 上且不冒泡），所以在它的设置里刚开好开关时，回到配图面板点一下「重新检测」即可。
- **Cosmos 的能力是假设的。** 它没有能力协商接口，适配器一律按「全支持」上报，所以 Cosmos + ComfyUI 下人物位置与提示词被静默忽略这件事，界面既探测不到也提示不了——只能靠这份文档说明。
- **ComfyUI 会绑定当前角色/用户头像。** 若 Cosmos 当前工作流把图片绑定设成「当前角色头像」或「当前用户头像」，那么为 A 聊天配图而人停留在 B 聊天时，会上传 **B 聊天**的头像作为参考图，画错人且构成跨聊天数据外泄。小剧场读不到 Cosmos 的私有设置，无法探测也无法阻止。**建议把工作流的图片绑定改成本地上传。**
- **用户不再是「所见即所发」。** 面板里编辑的是核心内容提示词，最终请求还会被后端追加预设、质量词、UC 词与 LoRA 触发词。
- **选景依赖插件自己的 API 方案**，默认跟随小剧场当前激活方案。生图后端的 Prompt LLM 配置不参与配图。
- **灯箱只在配图面板里。** 收藏阅读页与导出的 HTML 仍然是正文内嵌图（`<a target="_blank">`，点开是新标签页），不换成灯箱。
- **灯箱一次只放一张**（你点的那张），不能左右翻候选，也不在生成完成后自动弹出。想比较候选请回到图库。
- **「换个画面」不保证换掉。** 排除表只是素材里的一段，正文里若只有一个可落笔的瞬间，模型会复用同一幅（面板会明说）。要精确指定画面请用「本次额外要求」。
- **托管条目的默认文案不会随插件升级自动更新**，需要在那一条上点 ↺ 还原。见「托管条目」一节。
- **配图记录读不出来时面板会说明，不会自动重试。** 主界面不再自己读记录（那条路径随按钮一起删了），失败信息只落在面板状态行上，重开面板即重读。
- **自动配图默认关闭，且只在单次演绎 / 重演后触发。** 续写、队列生成与 ST 事件触发的自动演绎都**不会**自动配图 —— 那几种是无人看着的连续生成，跟着配图会一口气烧掉多张额度。
- **自动配图一次只跑一个。** 上一张还在配时又完成一轮，那一轮跳过并提示一句；不会排队，也不会并发。
- **自动配图没有「开始」提示，面板关着时也停不下来**（内容区那个按钮在 5.4 删掉了）。跑完才有一条 toastr；想中途取消或看进度，打开配图面板即可接管。
- **自动配图与面板任务可能同时在跑**（例如自动任务还没完，你又给另一轮手动点了「生成图片」）。两边写的是不同场景的记录，`mutateScene` 会串行化写盘所以不会写坏，但那是两次真实的选景与生图 —— 限流与费用由你自己权衡。
- **删除前要通读所有收藏正文**才能确认一个文件是否还有人引用（收藏索引里不带配图路径）。收藏很多时，点下删除到弹出确认框之间会有一次短暂的检查等待，面板状态栏会显示「正在检查图片引用…」。
- **删除不可撤销**，没有回收站。删除判定用并发上限读取收藏，若某个收藏正文读不出来，会**保守地不删任何图片文件**（只从本轮记录移除），并在确认框里说明。
- **客户端没有列目录的接口**（酒馆不提供），所以磁盘上历史遗留的孤儿图片无法在界面里枚举清理；能够精确回收的只有「被本次改写取代的场景记录」和「刚刚被删掉且无人引用的图片」。
- **从备份恢复时写入的场景记录**不会走 `mutateScene`，因此恢复前那份记录会成为孤儿（当前不清理）。
