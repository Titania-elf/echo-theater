# 盲盒剧本 ＋ 导演引导模式 — 方案

> 设计定稿 2026-10-11。本文件是实现前的权威设计记录；落地过程中若有偏离，以改动同时更新本文件为准。

## 1. 目标与玩家体验

把现有大纲从「平铺、可见、手动选候选」升级出一条新路径：用户只给一个大方向，模型生成一套**分层且封印**的剧本，连作者本人都看不到内容；盲玩时后台「导演」每回合悄悄把 AI 的原生回复往下一个封印事件轻推。最终体验是——你照常 RP、随便浪支线，却总能被惊喜地引着撞上自己当初规划的节拍，而且不跑偏主线。

**与现有「看得见、手动选候选」的大纲工作流并存，不取代。**

## 2. 数据模型

方案（plan）新增**类型**字段：`normal`（现有）/ `blindbox`（新）。

盲盒方案的结构是两层：

```
盲盒方案
├─ meta: { 基调走向, 节点数, 红线禁忌, sealed: true, unsealed: false }
├─ 节点[]  （硬锚 / 必达里程碑）
│   每个节点: { title, 达成状态描述, 其后的关键事件[] }
│       关键事件[]: { 内容(封印), status: 未到/进行中/已达成/已跳过 }
└─ progress: { 当前节点, 当前关键事件, revealed[] }
```

- **节点 = 必达硬锚**，**关键事件 = 软垫脚石**（可轻推、可容忍跳过、可被支线顺带完成）。
- 每段关键事件数由用户填，下限 3、上限 10。
- `revealed[]` 驱动回顾墙：某条判定达成/跳过就进这里，变成可回看的历史。

## 3. 下单（创建）流程

沿用现有大纲生成流，输入项：

1. **故事基调走向**（自由文本，大方向）
2. **节点数**（输入框）
3. **每段关键事件数**（输入框，默认下限 3，上限 10）
4. **红线/禁忌**（可选）—— 内容看不见，这是唯一能约束模型别生成你恶心的东西的闸门。

生成完**立即封印**，不摊开给用户看。

## 4. 封印与剧透逃生

**封印是「对用户」封印、对后台判定模型不封印**——判定必须读明文才能引导。要堵死所有现成泄题口：

- raw 响应历史与导出（`pushRawResponseHistory` / `exportRawResponseHistory`）
- debug 窗（最终提示词里会带封印内容）
- 生成后默认摊开的编辑表格

盲盒方案一律不往这些视图灌明文。

**诚实前提**：数据存在用户自己机器的 extData／聊天文件里，封印只做到「防手滑、防不经意瞄到」，不是加密；铁了心翻文件一定看得到——那正是剧透逃生这扇正门的用途。

**剧透逃生 = 整本解封（A）**：单向门，解封前弹确认「看了就没惊喜了，确定？」。解了回不去，不做假装封回。解封后复用普通方案表格看／手改（质量兜底的 C）。另一半兜底 B：不看内容、把某一段**整段盲重掷**。

## 5. 导演引擎（触发与注入）

- **开关**：某盲盒方案成为当前聊天的激活方案 ⟹ 导演默认开（盲盒必然依赖导演）。保留**手动暂停**开关。
- **循环**：每条**原生回复结束**（`GENERATION_ENDED`）→ 后台跑一次判定（复用大纲 API，走插件自有链路、不 emit `GENERATION_*`，不会递归自触发）：当前关键事件达成了吗？被支线顺带做了／变没意义了吗（可跳过/改写）？剧情偏多少、该多大力气拉？—— **达成/跳过/力度全交给模型每回合判**。产出下一回合引导指令 ＋ 更新进度 ＋ 把达成/跳过的事件推进回顾墙。
- **注入**：`setExtensionPrompt`（`role=system`，不落聊天记录），**持续挂着、刷新而非清除**；用**独立注入键**与一次性的节奏把控共存。
- **延迟藏在**回复结束后、用户读/打字的间隙后台跑完，下一条生成时引导已就位。
- **换聊天**（`CHAT_CHANGED`）：清注入，按新聊天激活方案重估。
- **两级强度**：两节点之间放开随便浪（闭嘴或轻推），临近下一节点才收紧往回拉。
- **抗楼层总结/隐藏**（A+B）：聊天变长后玩家常用总结插件折叠正文、隐藏楼层（置 `is_system`/`is_hidden`）——否则导演既读不到原始楼层、也读不到替代它们的摘要，会对已触发事件视而不见。两条对策：
  - **A**：导演专用的取正文函数**不**过滤隐藏/系统楼层（`collectRecentChatText(n, {includeHidden:true})`），既能读到刚隐藏的原文、也能读到摘要那条消息；摘要常不带白名单标签，隐藏楼层退回原文免得被洗空。带【背景】前缀下发，让判定模型知道这是摘要/已隐藏段。
  - **B**：导演每把一个事件判成 done/skipped，就在该事件上留一句 `recap`（实际怎么发生的），随骨架 JSON 回灌。这是**不随楼层隐藏消失的 durable 记忆**：骨架里已 done/skipped 的事件一律当既成事实，判定模型不得因最近正文看不到就翻回未达成。recap 顺带喂给前端回顾墙。
  - **普通大纲流同病同治（部分）**：推荐剧情 / 节奏把控读正文也走 includeHidden（否则前文一折叠，模型既判不出进度、也凑不出贴剧情的候选）。但**不给它另造 recap 记忆**——普通流的进度指针 `currentItemIndex` 本就持久化，且 `parseRecommendationResponse` 在模型判不出时回退保留旧指针、不冲掉，等于已有一层弱 durable 记忆；再叠 recap 会和「进度交给模型读正文自行判断」的既定设计打架（当年删 `{{progressHint}}` 正是这个理）。故普通流只补 A（情境感知），B 维持现状。

## 6. 前端表现

UI 按**当前激活方案类型自动切**：

- **普通方案** → 现有可编辑表格 ＋ 推荐剧情，原样不动。
- **盲盒方案** → 盲盒进度视图：节点骨架 ＋ 关键事件进度点（实心=已达成/揭晓，空心=未到/封印）＋ 回顾墙，**无任何未来文字**。
- **盲盒 ＋ 已解封** → 复用普通方案表格看/改。

消息流里的「剧情推进」横条：盲盒激活时推荐剧情隐身，横条退化成「引导中 · 进度点」状态灯。

## 7. 与现有系统的复用关系

- 生成/判定复用大纲无头 API 与连接体系；注入复用 `setExtensionPrompt`（新开导演专用键，与 `PACING_PROMPT_KEY` 并存）；进度沿用「模型读正文自行判断」。
- 导演与封印**正交**：盲盒必然用导演；导演底座日后也能单独给普通可见方案加「自动引导」——**v1 先捆在盲盒里，别摊大**。

## 8. 落地顺序

1. 数据模型 ＋ 方案类型 ＋ 下单输入 ＋ 封印生成（含堵掉泄题口）
2. 盲盒进度视图 ＋ 回顾墙 ＋ 剧透逃生（A/单向/确认）
3. 导演引擎（判定 ＋ 注入 ＋ 生命周期 ＋ 两级强度 ＋ 动态跳过）
4. 横条退化 ＋ 与推荐剧情/节奏把控共存收尾 ＋ 打磨
