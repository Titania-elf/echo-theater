# 盲盒剧本 ＋ 导演引导模式 — 方案

> 设计定稿 2026-10-11。本文件是实现前的权威设计记录；落地过程中若有偏离，以改动同时更新本文件为准。

## 1. 目标与玩家体验

把现有大纲从「平铺、可见、手动选候选」升级出一条新路径：用户只给一个大方向，模型生成一套**分层且封印**的剧本，连作者本人都看不到内容；盲玩时后台「导演」每回合悄悄把 AI 的原生回复往下一个封印事件轻推。最终体验是——你照常 RP、随便浪支线，却总能被惊喜地引着撞上自己当初规划的节拍，而且不跑偏主线。

**与现有「看得见、手动选候选」的大纲工作流并存，不取代。**

## 2. 数据模型

方案（plan）新增**类型**字段：`normal`（现有）/ `blindbox`（新）。

盲盒方案的结构是两层：

```
盲盒方案
├─ meta: { 基调走向, 节点数, 红线禁忌, sealed: true, unsealed: false }
├─ 节点[]  （硬锚 / 必达里程碑）
│   每个节点: { title, 达成状态描述, 其后的关键事件[] }
│       关键事件[]: { 内容(封印), status: 未到/进行中/已达成/已跳过 }
└─ progress: { 当前节点, 当前关键事件, revealed[] }
```

- **节点 = 必达硬锚**，**关键事件 = 软垫脚石**（可轻推、可容忍跳过、可被支线顺带完成）。
- 每段关键事件数由用户填，下限 3、上限 10。
- `revealed[]` 驱动回顾墙：某条判定达成/跳过就进这里，变成可回看的历史。

## 3. 下单（创建）流程

沿用现有大纲生成流，输入项：

1. **故事基调走向**（自由文本，大方向）
2. **节点数**（输入框）
3. **每段关键事件数**（输入框，默认下限 3，上限 10）
4. **红线/禁忌**（可选）—— 内容看不见，这是唯一能约束模型别生成你恶心的东西的闸门。

生成完**立即封印**，不摊开给用户看。

## 4. 封印与剧透逃生

**封印是「对用户」封印、对后台判定模型不封印**——判定必须读明文才能引导。要堵死所有现成泄题口：

- raw 响应历史与导出（`pushRawResponseHistory` / `exportRawResponseHistory`）
- debug 窗（最终提示词里会带封印内容）
- 生成后默认摊开的编辑表格

盲盒方案一律不往这些视图灌明文。

**诚实前提**：数据存在用户自己机器的 extData／聊天文件里，封印只做到「防手滑、防不经意瞄到」，不是加密；铁了心翻文件一定看得到——那正是剧透逃生这扇正门的用途。

**剧透逃生 = 整本解封（A）**：单向门，解封前弹确认「看了就没惊喜了，确定？」。解了回不去，不做假装封回。解封后复用普通方案表格看／手改（质量兜底的 C）。另一半兜底 B：不看内容、把某一段**整段盲重掷**。

## 5. 导演引擎（触发与注入）

- **开关**：某盲盒方案成为当前聊天的激活方案 ⟹ 导演默认开（盲盒必然依赖导演）。保留**手动暂停**开关。
- **循环**：每条**原生回复结束**（`GENERATION_ENDED`）→ 后台跑一次判定（复用大纲 API，走插件自有链路、不 emit `GENERATION_*`，不会递归自触发）：当前关键事件达成了吗？被支线顺带做了／变没意义了吗（可跳过/改写）？剧情偏多少、该多大力气拉？—— **达成/跳过/力度全交给模型每回合判**。产出下一回合引导指令 ＋ 更新进度 ＋ 把达成/跳过的事件推进回顾墙。
- **注入**：`setExtensionPrompt`（`role=system`，不落聊天记录），**持续挂着、刷新而非清除**；用**独立注入键**与一次性的节奏把控共存。
- **延迟藏在**回复结束后、用户读/打字的间隙后台跑完，下一条生成时引导已就位。
- **换聊天**（`CHAT_CHANGED`）：清注入，按新聊天激活方案重估。
- **两级强度**：两节点之间放开随便浪（闭嘴或轻推），临近下一节点才收紧往回拉。
- **抗楼层总结/隐藏**（A+B）：聊天变长后玩家常用总结插件折叠正文、隐藏楼层（置 `is_system`/`is_hidden`）——否则导演既读不到原始楼层、也读不到替代它们的摘要，会对已触发事件视而不见。两条对策：
  - **A**：导演专用的取正文函数**不**过滤隐藏/系统楼层（`collectRecentChatText(n, {includeHidden:true})`），既能读到刚隐藏的原文、也能读到摘要那条消息；摘要常不带白名单标签，隐藏楼层退回原文免得被洗空。带【背景】前缀下发，让判定模型知道这是摘要/已隐藏段。
  - **B**：导演每把一个事件判成 done/skipped，就在该事件上留一句 `recap`（实际怎么发生的），随骨架 JSON 回灌。这是**不随楼层隐藏消失的 durable 记忆**：骨架里已 done/skipped 的事件一律当既成事实，判定模型不得因最近正文看不到就翻回未达成。recap 顺带喂给前端回顾墙。
  - **普通大纲流同病同治（部分）**：推荐剧情 / 节奏把控读正文也走 includeHidden（否则前文一折叠，模型既判不出进度、也凑不出贴剧情的候选）。但**不给它另造 recap 记忆**——普通流的进度指针 `currentItemIndex` 本就持久化，且 `parseRecommendationResponse` 在模型判不出时回退保留旧指针、不冲掉，等于已有一层弱 durable 记忆；再叠 recap 会和「进度交给模型读正文自行判断」的既定设计打架（当年删 `{{progressHint}}` 正是这个理）。故普通流只补 A（情境感知），B 维持现状。

## 6. 前端表现

UI 按**当前激活方案类型自动切**：

- **普通方案** → 现有可编辑表格 ＋ 推荐剧情，原样不动。
- **盲盒方案** → 盲盒进度视图：节点骨架 ＋ 关键事件进度点（实心=已达成/揭晓，空心=未到/封印）＋ 导演设置（严格度/停留），**无任何未来文字**。逐段揭晓的**回顾墙已迁到消息流里的「剧情推进」面板**（见 §10），这里只留骨架概览与指路提示。
- **盲盒 ＋ 已解封** → 复用普通方案表格看/改。

消息流里的「剧情推进」横条：盲盒激活时推荐剧情隐身，横条退化成「引导中 · 进度点」状态灯。

## 7. 与现有系统的复用关系

- 生成/判定复用大纲无头 API 与连接体系；注入复用 `setExtensionPrompt`（新开导演专用键，与 `PACING_PROMPT_KEY` 并存）；进度沿用「模型读正文自行判断」。
- 导演与封印**正交**：盲盒必然用导演；导演底座日后也能单独给普通可见方案加「自动引导」——**v1 先捆在盲盒里，别摊大**。

## 8. 落地顺序

1. 数据模型 ＋ 方案类型 ＋ 下单输入 ＋ 封印生成（含堵掉泄题口）
2. 盲盒进度视图 ＋ 回顾墙 ＋ 剧透逃生（A/单向/确认）
3. 导演引擎（判定 ＋ 注入 ＋ 生命周期 ＋ 两级强度 ＋ 动态跳过）
4. 横条退化 ＋ 与推荐剧情/节奏把控共存收尾 ＋ 打磨

## 9. v2：判定严格度与时间尺度（2026-10-12）

v1 实测两个毛病：**判定太松**（一个关键事件常常活不过 1~2 拍，十几回合整本跑完）和**时间跨度太小**（节点之间挤在连续几天里）。根因不在"提示词写得不够狠"，而在缺字段与缺代码闸门。

### 9.1 时间跨度（生成侧）

v1 的盲盒生成模板把普通大纲模板里的三条时间规则整个丢了：没有 time/span 字段、没有"先定总时长"、没有"禁止逐日推进"；剩下的"因果衔接、用因此/但是"反而在**压缩**时间（南方公园法则要的是即时后果）。对策：

- 下单新增**故事总时长**（`bb.timescale`，带快捷档），渲染成 `{{timescale}}`；
- 节点与事件都加 `span`（时间跨度标记），生成模板补齐"先认总时长再分配 span / 禁止逐日推进 / 同节点内事件之间也要有间隔 / **跨节点是全段最大的一跳** / 跳过的时间里的关键变化直接写进 content"，并要求返回前自检 span 单调且累加≈总时长；
- 判定侧把 span 一起下发，且**指针换人且新目标带 span 时，注入里追加一条确定性的「时间推移」指令**——RP 里的时间推移必须由旁白明说，光在骨架里写"两周后"没人会执行。

### 9.2 判定严格度（判定侧）

| 层 | 做法 |
|---|---|
| 靶子可验证 | 事件新增 `done_when`（1~3 条可观测、可指认的成立条件）与 `beats`（拍数预算）；节点新增 `anchor_when` |
| 三档回报 | `done` / `skipped` / **`progress`**（这一拍在推进但没达成，只记笔记不消耗事件）。v1 只有前两档，模型想说"在推进"时唯一的出口就是 done |
| 要证据 | 每条回报要 `evidence` ＋ `evidence_floor`（正文带 `#楼层号`下发）＋ `criteria_met` ＋ `confidence` |
| 代码闸门 | 每回合最多 1 个 done（按下标取最早）；目标指针由代码推导为"第一个未翻事件"，模型的 target 不采信；跨节点要 `anchor_met` 双钥匙（否则 `awaitingAnchor` 把指针按在节点末尾）；停留拍数未达 beats 时降级；`evidence_floor ≤ 上次判定楼层`作废；skipped 要 reason 且不许越过当前目标批量跳未来事件；已翻过的不许翻回 |
| 严格度旋钮 | `loose`＝v1 老行为 / `standard`（默认）/ `strict`。游玩途中可改，只影响以后的判定 |

闸门全部在 `applyDirectorDecision`，被拒绝的回报降级成 `progress` 并把证据留成事件笔记（随骨架回灌），不白判。`describeStrictness()` 是喂给判定模型的契约文本——**改闸门必须同步改它**。

### 9.3 触发时机与可回滚

`GENERATION_ENDED` 其实来自 ST 的 `hideStopButton()`：swipe、continue、impersonate、乃至总结插件的 quiet 生成都会发一次。v1 对每一次都判一遍（同一段正文被判多次＝多掷几次骰），且被 swipe 丢弃的那条回复**永久消耗**了事件。对策：

- `getDirectorTrigger()` 算一个签名（末楼层下标＋swipe 下标＋文本指纹）：末楼层不是"可见的角色回复"就不判，签名没变就不判；
- `bb.journal` 记每拍改了什么（含停留计数），同一楼层换 swipe 时 `rollbackJournalFrom()` 整笔撤回后再重判；
- 判定返回解析不出来（多半是 max_tokens 截断）时**保留上一拍的注入、什么都不落盘**，尤其不推进 `lastJudged`，否则这段正文的证据会被白白作废；
- 导演有了独立的采样参数组（temp 0.15 / maxTokens 2048）与独立的读取层数（默认 6 层，0=跟随剧情推进）。

### 9.4 两个必须记住的坑

1. **`normalizeBlindbox` 是白名单式对象字面量**：没写进去的字段会在落盘时蒸发。v1 的 `directorPaused` 就栽在这儿（判定落盘时被洗掉，暂停只靠 `undefined !== true` 侥幸成立）。新增任何运行态字段都要同步补进 normalize，并补一条单测。
2. **`savePromptTemplates` 整块存五类模板**：用户只要打开过设置并保存，blindbox/director 模板就被冻结在旧版，改默认模板对他们无效。故 `getPromptTemplates()` 里对这两类也做了 legacy 探测重置（缺 `done_when` / 缺 `evidence_floor` 即重置），与 rolling 同构。

## 10. 解锁界面：阶段化揭晓 ＋ 解锁音效（2026-10-12）

**问题**：回顾墙原本在「大纲生成」窗口里——那是个管理界面，玩家游玩时盯着的是消息流底部的「剧情推进」横条。结果是每解锁一拍都要专门开一次大纲窗口，没人会这么做（`sceneAdvanceBubble.js` 里那句"想看回顾墙请到「大纲生成」窗口"就是这个错位的自白）。

### 10.1 搬家 ＋ 阶段化

回顾墙迁入「剧情推进」面板（`buildBlindboxBody`），重做成**阶段化解锁界面**：阶段＝节点。

| 阶段状态 | 面板给什么 |
|---|---|
| `cleared`（该节点事件全部翻过，且指针已离开） | 揭晓**节点标题 ＋ 硬锚 ＋ 全部事件**（含 recap/skip 理由），可折叠，默认展开最近通关的那个 |
| `current` | 只给"阶段 N · 进行中 x/y"，事件里**已翻过的照常揭晓**、未翻的只给"未解锁/已走 N 拍"＋一条微光占位条 |
| `sealed` | 一行"阶段 N · x 件"，连事件行都不画 |

**用户定的口径**：进行中的阶段**不**显示标题与硬锚，只在通关后揭晓——揭晓本身就是奖励。

四条由代码保证的规则（`blindboxReveal.buildRevealView`，纯函数可测）：
1. **未解锁项在数据层就没有内容**：不给 `content`/`span`/`doneWhen`/`notes`，不是靠渲染时记得别写；测试直接扫整个视图的序列化串找机密子串。
2. **"通关"按事件判定，不按进度下标**：宽松档下模型能把指针跳到未翻完的节点之后，按下标判会把那个节点的硬锚提前泄出去（硬锚是最强的剧透）。`cleared = 该节点事件非空且全部翻过`。
3. **硬锚未落地（`awaitingAnchor`）不算通关**：事件都翻过但导演还在收束那一拍时，标题与硬锚一律不揭晓，只显示"在等一个转折真正落地"。等指针真走了才揭晓。
4. 面板底部与横条的**停留拍数**不是剧情内容（讲的是玩家自己打了几拍），封印态也能显示。

### 10.2 解锁账本（`bb.announced` / `bb.viewed` / `bb.marksReady`）

两件事要分别记账，因为**发生时机不同**：音效在解锁那一刻响（判定跑完），揭晓动画在玩家下次打开面板时才播（面板活不过一条新楼层——它是插在最后一条 AI 楼层的横条里的）。

- 标记格式 `"e:节点.事件"` / `"s:节点"`，两张表：`announced`=已响过音效、`viewed`=已做过揭晓动画，各封顶 300 条。
- `marksReady`：本功能上线前的老存档没有这两张表，首次接触时 `backfillRevealMarks` 静默补记——否则第一次打开会噼里啪啦响一串陈年旧账。
- **静音也照记账，只压播放**：否则静音期间攒下的解锁会在重新打开音效时一起炸出来。
- **一回合最多响一声**（`pickUnlockCue`：阶段音优先，否则事件音）：宽松档一回合可能翻过好几个事件，逐个响就是噪音。
- **swipe 回滚要剪标记**（`rollbackJournalFrom`）：被撤回的事件连它的阶段标记一起剪掉，否则同一段剧情重判时永远不再响——而"重新解锁"正是最该响的那一次。
- **重掷一本要清账本**（`sealWithNodes`）：新本子沿用同一套下标，不清就静默失效（最难查的一种）。
- ⚠ 这三个字段必须写进 `normalizeBlindbox` 的白名单，否则每次落盘都被洗掉（`directorPaused` 栽过一次）。

### 10.3 触发与刷新通路

ST 的渲染事件都在判定**之前**发完（判定要等一次 API 往返），所以横条上的进度与角标都是旧的；面板更是通常已被新楼层收掉。通路：

`GENERATION_ENDED` →（`directorInjection`）`runDirectorTurn(trigger)` **返回 `{planId}`** → 动态 import `sceneAdvanceBubble.js` → `notifyBlindboxUnlocks(planId)`：结账 ＋ 响一声 ＋ 给横条加"有新解锁"角标 ＋ 面板若还开着就地刷新。

- **planId 必须在判定前捕获**：判定期间用户可能切换激活方案，事后重读 extData 会拿错本子。
- 横条没开（`outline_entry.show_outline_actions` 关）时**账照记、不响**：响一声却没有任何地方能看，只会让人找不到北；等横条打开，那段没看过的历史会补做一次揭晓动画。
- 音效由 `directorInjection`（core 层）经动态 import 交接给 UI 层，保持 core 不静态依赖 UI。

### 10.4 音效：运行时合成，不带音频文件

仓库没有任何音频设施（`build.js` 只打包 JS＋内联 CSS，无 assets 目录，`manifest.json` 只声明 index.js），为一声 300ms 的音效新造"资源＋打包＋路径"机制不划算。故 `src/core/unlockChime.js`：

- **事件解锁**：C6 → G6 纯五度，两个音。**刻意只有两个**——三个音往上走就是手机通知音。
- **阶段通关**：C6 → E6 → G6 → C7 琶音（顶音压低，不然最扎耳）＋ 2.76× 分音做钟感。两条同一调性，后者是前者的"说完整版"。
- 音色：正弦谐波堆（f/2f/3f）＋ 三角波 3ms 起音瞬态；总线低通 5.2k 削毛刺；两个固定延迟抽头做空间感（比 ConvolverNode 便宜也好听）；音量平方律映射（30% 已经不轻）。
- **自动播放策略**：解锁发生在 `GENERATION_ENDED` 之后，**不是**用户手势，context 会是 suspended。此时排队音符不会立刻响、而是等恢复后一起炸出来——所以 `ctx.state !== 'running'` 时只 `resume()` 不排音符，宁可这一声没有。`initUnlockSound()` 在首次 pointerdown 时就恢复一次（`entry.js` 挂）。
- 设置：`blindbox_reveal { enabled, volume, cue_event }`（**独立顶层块**——`settingsWindow.js` 保存时会把 `director` 整个换掉）。音量在面板底部的循环按钮上（关/轻/中/响，每切一档当场试听），设置抽屉里有总开关、音量条与试听（一次听完两档）。

### 10.5 动效与无障碍

`t-bb-reveal-in`（opacity＋位移＋blur 3px→0，0.32s，从模糊到清晰的揭晓感）与 `t-bb-shimmer-sweep`（锁定占位条的微光，只用在当前阶段那两三条锁行）声明在 `css/01-base/keyframes.css`（阻断项 A7/R6 要求）；横条角标复用既有 `t-pulse-green`。样式全部用语义 token，深浅主题自动跟随。本仓库第一个 `@media (prefers-reduced-motion: reduce)` 兜底也在这里：动画停掉，状态信息留在原地。

### 10.6 已知边界

- 账本存在 `plan.blindbox` 上（与进度同层），所以**一本＝一周目**：同一个方案在两个聊天里玩会共享进度与账本。这是 v1 起的既有设计（§2），本次不动。
- 音效首次播放若不在用户手势内会被浏览器拦下（静默失败）；此后任何一次点击都会恢复音频上下文。
